Stack Corruption Forensics

Two memory bugs in a 40-line C program, built 96 ways on four platforms. Where the stray write lands, what each build does, and which tools notice are different almost everywhere. Every result on this page was produced by CI.

All sandboxes

The program and its two bugs

Bug 1, NULL store: *j = 0 writes through a null pointer. Bug 2, off-by-one: i <= LEN runs the loop five times, so b[4] is written: one int past the end of main's array, into whatever main's frame keeps there.

Both are undefined behavior: C promises nothing about what happens. Here is what actually happened:
